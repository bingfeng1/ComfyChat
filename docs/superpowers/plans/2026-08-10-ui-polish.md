# UI Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace bespoke CSS-driven UI of ComfyChat frontend with Element Plus components + SCSS tooling per `docs/superpowers/specs/2026-08-10-ui-polish-design.md`. Result: consistent visual language, light theme only, no behavior changes.

**Architecture:** On-demand Element Plus via `unplugin-vue-components` + `unplugin-auto-import`. App shell uses `el-container` family; pages use `el-table` + `el-input` + `el-select` + `el-button`; all modals route through a thin `Modal.vue` wrapper that exposes `el-dialog` underneath. SCSS lives in a small `src/styles/` folder with `_variables.scss` for app-specific tokens and `_element-overrides.scss` for EP theme tweaks (brand color `#0ea5e9`).

**Tech Stack:** Vue 3.4 (composition API + `<script setup lang="ts">`), Vite 5, Vue Router 4, Element Plus 2.11+, `@element-plus/icons-vue` 2.3+, sass 1.77+, unplugin-vue-components 0.27+, unplugin-auto-import 0.18+.

## Global Constraints

[Project-wide rules copied verbatim from spec + AGENTS.md. Applies to every task unless that task overrides.]

- **Light-only theme.** No dark mode toggle ships. CSS variables are introduced for tooling only.
- **No behavior changes.** Routing, Pinia, `useWorkflows.ts`/`useGenerations.ts`, `services/api.ts`, all backend code, all backend tests stay untouched.
- **No frontend test framework exists.** Per AGENTS.md, validation = `npm run typecheck` + `npm run build` + manual smoke. There is no `npm run test` or `vitest`. Do not invent one.
- **Vite dev host stays `127.0.0.1`.** Do not touch `vite.config.ts` server host binding.
- **Element Plus is auto-imported.** Do not write `import { ElButton } from 'element-plus'` in component `<script setup>`. The resolver injects the component (and its style imports) per template usage. Same for icons — use as `<component :is="…">` only when truly dynamic, otherwise import the icon symbol directly: `import { Folder } from '@element-plus/icons-vue';` (icons are not auto-imported by the resolver).
- **Auto-import plugin order.** `autoImport` before `components` (or order does not matter functionally; we still keep that order).
- **Auto-import styles extension.** Use `styleExtension: 'scss'` so EP variable overrides compile.
- **Pinia/Vue Router scaffolding untouched.** `src/main.ts` already mounts App + router + pinia; we only add an `app.use(ElementPlus, …)` line for locale. Do not refactor app bootstrap.
- **Workspace conventions:** Python venv at `backend/.venv/Scripts/python` (Windows PowerShell). `frontend/.npmrc` already configures the npm mirror — do not run `npm config set` globally. `start-dev.ps1` / `stop-dev.ps1` manage dev processes; do not run `npm run dev` or `uvicorn` in the foreground for verification.
- **`<style>` blocks.** Set `lang="scss"` and `@use '@/styles/variables' as *;` at the top of every component that needs SCSS variables. Plain CSS in inline hex codes is deleted where EP now provides the value.
- **Bulk file changes:** use `replaceAll` only when the same string occurs identically in many places and you have visually confirmed there are no false positives. Otherwise, prefer targeted edits.

import { useWorkflows } from "./useWorkflows";
import type { WorkflowSummary } from "@/types/api";

const {
  items,
  loading,
  error,
  sourceFilter,
  search,
  importing,
  syncing,
  syncMsg,
  conflict,
  onFileChosen,
  doSearch,
  doSync,
  removeWorkflow,
  clearConflict,

const detail = ref<WorkflowSummary | null>(null);
const historyOf = ref<WorkflowSummary | null>(null);
const configOf = ref<WorkflowSummary | null>(null);
const confirmDelete = ref<WorkflowSummary | null>(null);
const pendingFile = ref<File | null>(null);

async function handleChosen(file: File) {
  pendingFile.value = file;
  const r = await onFileChosen(file);
  if (r && r.ok) {
    pendingFile.value = null;
    clearConflict();
  }
}

async function resolveConflict(
  action: "rename" | "overwrite" | "cancel",
  name?: string,
) {
  if (action === "cancel") {
    pendingFile.value = null;
    clearConflict();
    return;
  }
  const file = pendingFile.value;
  if (!file) {
    clearConflict();
    alert("文件已失效，请重新选择。");
    return;
  }
  if (action === "rename") {
    if (!name) return;
    const r = await onFileChosen(file, { name });
    if (r?.ok) {
      pendingFile.value = null;
      clearConflict();
    }
  } else {
    const r = await onFileChosen(file, { overwrite: true });
    if (r?.ok) {
      pendingFile.value = null;
      clearConflict();
    }
  }
}

async function onExport(id: string) {
  const res = await (await import("@/services/api")).api.workflows.export(id);
  const blob = await res.blob();
  const cd = res.headers.get("Content-Disposition") ?? "";
  const m = cd.match(/filename="?([^";]+)"?/);
  const filename = m ? m[1] : "workflow.json";
  const url = URL.createObjectURL(blob);
  const a = document.createElement("a");
  a.href = url;
  a.download = filename;
  a.click();
  URL.revokeObjectURL(url);
}

function fmtSize(bytes: number) {
  if (bytes < 1024) return `${bytes}B`;
  if (bytes < 1024 * 1024) return `${(bytes / 1024).toFixed(1)}KB`;
  return `${(bytes / 1024 / 1024).toFixed(1)}MB`;
}

function fmtTime(iso: string) {
  return new Date(iso).toLocaleString();
}

  browse: "ComfyUI",
  import: "导入",
};
